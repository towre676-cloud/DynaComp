# DynaComp

**Compile the dynamics needed by a target, and account for what a reduction loses.** DynaComp constructs exact observable quotients of rational linear systems, sparse interaction networks, autonomous and controlled polynomial systems with finite observable closure, switched systems, and finite deterministic partial machines. Version 0.7 asks whether a guarantee survives **forever**: rigorous all-time error brackets that can certify or *refute* a tolerance for every future time, exact Schur–Cohn/Hurwitz stability decisions with rational quadratic Lyapunov certificates, and sharp bounds over correlated (zonotopic) scenario domains. Version 0.6 adds sharp acceptance under time-varying convex mode uncertainty, count-lattice compression and reusable validated scenario execution. Version 0.5 adds sharp box-uniform general-direction enrichment, attaining counterexamples, sparse coefficient families and a thermal scenario workbench. Version 0.4 added Hankel-certified minimal realizations, weighted automaton and HMM minimization and equivalence with shortest counterexamples, exact parameter loci where a reduction closes only by accident, and scenario-certified direction enrichment. Version 0.3 adds a runnable inventory-network scenario application; version 0.2 introduced adaptive coordinate enrichment with uniform box guarantees, least-cost coordinate search, common reductions for coefficient families and exact output recurrences with input memory. This is a research implementation with executable demonstrations, not a general nonlinear reduction solver.

| Capability | Entry point | Accepted by |
|---|---|---|
| Observable quotient (dense / sparse) | `compile_linear`, `compile_sparse` | EA = GE, EB = H, DE = C |
| Minimal input-output realization | `minimal_realization` | AP = PF, B = PK, EF = GE, EK = H, DE = CP **and** a nonsingular Hankel block of the original |
| Coefficient families / switched closure | `compile_family`, `compile_switched` | E A_s = G_s E for every operator s |
| Weighted automaton / HMM minimization | `minimize_automaton` | forward and backward identities plus a nonsingular Hankel block of word weights |
| Weighted language equivalence | `check_equivalence` | invariant span annihilating η₁ − η₂, or a shortest distinguishing word |
| Structural vs accidental closure, one parameter | `parametric_analysis` | Sturm-isolated real roots of the exact rank-drop polynomial |
| Adaptive coordinates, uniform over boxes | `adaptive_coordinates`, `optimal_coordinates` | rational box envelopes ≤ tolerance |
| Sharp time-varying convex uncertainty | `switching_enrichment` | commuting count-lattice DP or budgeted enumeration, plus attaining mode/input witness |
| General directions, sharp uniform boxes | `uniform_enrichment`, `sharp_box_bound` | direct error kernels and an attaining witness |
| Sparse coefficient families | `compile_sparse_family` | common sparse transition/input/output identities |
| Direction enrichment, per scenario | `greedy_enrichment` | recomputed rational envelopes ≤ tolerance |
| Output recurrences with input memory | `compile_output_memory` | rational recurrence identities |
| Polynomial closure, autonomous / controlled | `compile_polynomial`, `compile_controlled_polynomial` | coefficient-by-coefficient pullback identities |
| Finite partial machines | `compile_finite` | homomorphism plus a distinguishing word per class pair |
| All-time error bracket / enrichment | `all_time_bound`, `all_time_enrichment` | exact metric contraction, then a rigorous [lower, upper] bracket for every t ≥ 0; lower bound is attained |
| Stability decision and certificate | `schur_stable`, `hurwitz_stable`, `quadratic_certificate`, `continuous_certificate` | Schur–Cohn on the exact characteristic polynomial; exact Sylvester tests of P ≻ 0 and γP − AᵀPA ≻ 0 |
| Switching stability | `common_quadratic_certificate` | one P contracting every mode |
| Correlated scenario domains | `sharp_zonotope_bound` | sharp supremum with an attaining scenario, executed on replay |

The key question is whether a smaller state retains enough information to predict the requested output under future updates. When the initial representation fails, the linear compiler produces two states with the same representation and different next encoded states, then adds missing directions. Finite machines carry distinguishing experiments for every pair of retained classes. Polynomial compilation searches for features whose compositions with the update close exactly.

## Install and run

The exact core uses Python 3.10 or newer and the standard library. From the repository directory, install with `python -m pip install -e .`. NumPy is optional for snapshot proposals and the performance demonstration; install those extras with `python -m pip install -e '.[numerical]'`.

Run `python -m unittest discover -s tests -v`, `python examples/run_examples.py`, and `python examples/run_adaptive.py`. Run `python examples/thermal_plate.py` for the heated-plate application. Compile a supplied model with `python -m dynacomp.cli compile examples/adaptive_driver.json --output receipts/my_reduction.json`, then check its identities with `python -m dynacomp.cli replay receipts/my_reduction.json`. The CLI accepts `linear`, `sparse`, `polynomial`, `controlled_polynomial`, `finite`, `adaptive`, `family`, `memory`, `realization`, `switched`, `automaton`, `equivalence`, `parametric`, `enrichment`, `uniform_enrichment`, `sparse_family`, `switching_enrichment`, `stability`, `common_quadratic`, `all_time` and `zonotope` model kinds; every file in `examples/*.json` is a working specification. For example, `python -m dynacomp.cli compile examples/hmm_perturbed.json` returns the shortest observation word on which two weather HMMs disagree. Use rational strings such as `"1/2"`; the exact core rejects binary floating-point inputs.

## Does the guarantee survive forever? (0.7)

Run `python examples/thermal_forever.py`. The 0.5 nine-state plate model is certified below 0.1 for twenty steps, but under the same boxes held forever it is **refuted at t = 21**, and its all-time worst error is bracketed in **[3.26665003, 3.26665003]**, attained by a bang-bang heater word near t = 121; an independent binary64 simulation of the full plate reproduces the value. All-time enrichment, which adds steady-state moment directions C(I − A)⁻ʲ, finds a **seven-state model certified below 0.0998 for every t ≥ 0**. Read [the 0.7 chapter](docs/FOREVER.md) for the dual-metric rounding control that keeps the bracket rigorous over thousands of steps.

## Thermal scenarios and uniform general directions

Run `python applications/thermal_scenarios/run_demo.py`, or `dynacomp-thermal --output-dir thermal_results`. A 144-state synthetic plate compiles to nine states with a **sharp worst-case corner-mean error of about 0.08284**, below tolerance 0.1, over twenty steps for every independent initial temperature in [18,22] and heater input in [0,2]. Its certificate includes a concrete input/initial-state witness attaining the worst error. A separate seventeen-state sparse family remains exact for arbitrary time-varying conductance in [1/16,1/8]. The approximation's bound fixes conductance at 1/8.

The workbench reports full-model output intervals, threshold classifications and nominal/outage scenarios. The optional production batch executor runs about 9.6 times faster than full SciPy sparse evolution on the retained short-horizon case, but construction needs about 426 similarly sized batches to amortize. QR/evolution rounding is outside the rational error guarantee. Read [application instructions](applications/thermal_scenarios/README.md) and [the derivation](docs/UNIFORM.md) for the domains and cost accounting.

## Inventory-network scenario application

Compile a sparse fixed-routing stock model once, then evaluate batches of replenishment plans. The application reports regional stock at every time, cumulative dispatch, stock-floor violations and a conservation residual. Inputs use named supply channels and explicit node distributions. Local differences trigger aggregate refinement, and a group budget stops expensive unsuccessful compilation. Exact rational execution is available; the optional NumPy/SciPy backend handles scenarios in vectorized batches and is the same executor used in the performance benchmark.

Run `python applications/network_scenarios/run_demo.py` for the included 32-node example. For supplied JSON, use `dynacomp-network compile MODEL.json --output PLAN.json`, then `dynacomp-network run PLAN.json SCENARIOS.json --backend numpy --output REPORT.json --csv REPORT.csv`. The standard backend needs no optional dependencies; add `--exact` to obtain rational results. Read [application instructions](applications/network_scenarios/README.md) and [the proposed paid pilot](applications/network_scenarios/PILOT.md) for formats, event timing and acceptance criteria.

The retained synthetic benchmark compares the production vectorized executor against SciPy sparse evolution and a correctly hand-built aggregate. At 8,192 nodes, 128 scenarios and 96 steps, execution takes about 0.296 s full versus 0.00143 s compiled. Compilation and identity replay take about 0.714 s, so the first batch is **slower** overall; estimated amortization is about 195 queries in similarly sized batches. Hand aggregation takes about 0.000885 s and is faster than the automatic executor. A heterogeneous 32-node case retains all 32 states and offers no speed benefit. These are fixed-fraction synthetic networks, not measured industrial logistics workloads. JSON parsing and scenario ingestion are excluded from the kernel benchmark.

## What works now

For linear systems, DynaComp constructs the smallest invariant row space containing the target rows. Its packet contains an encoder E, reduced transition G, reduced input H and output D satisfying **EA = GE, EB = H and DE = C**. These identities imply identical outputs for every initial state and every finite input sequence. Independent packet replay checks the identities without rerunning the discovery algorithm. The sparse backend computes row pullbacks from nonzero entries instead of constructing a dense transition matrix.

The polynomial backend discovers exact feature dynamics by repeated polynomial pullback and rational row-space reduction. The example `x_next = x + y², y_next = y` closes with the two features x and y². Degree, feature and iteration limits return a resource-limit result; they do not establish that a finite closure is impossible. The finite backend respects partial-action definedness and checks a separate distinguishing word for each pair of quotient classes.

Approximate models are handled through the residual identity for a rational lift V. Bounds include hidden initial-state error, transition residual and input residual, with target-aware propagation through powers of A. They remain valid on finite horizons even when A has transient growth or unstable modes. Positive diagonal metrics can supply an exact weighted infinity-norm contraction margin; failure to find such a metric does not prove instability. Optional POD snapshot proposals are candidates and require subsequent error analysis.

Sparse aggregate refinement discovers which groups have closed sum dynamics. A 16-site ring with one local defect refines into nine aggregate classes, preserving the reflection pairs. Exact affine block composition can fast-forward repeated input words in logarithmically many matrix compositions, subject to the cost of growing rational numerators and denominators.

## New in 0.4

Read [the 0.4 companion chapter](docs/EXTENSIONS.md) for derivations and limits.

- **Minimal realization with a minimality proof.** Reachable-then-observable quotient for zero initial state. Replay recomputes a Hankel block from the *original* Markov parameters, which shows that no smaller realization exists.
- **Switched systems, weighted automata and HMMs.** Closure under every mode sequence, with each encoder row labelled by its experiment word and per-mode inputs. Schützenberger minimization, and Tzeng-style equivalence that returns a *shortest* distinguishing word or an invariant-span certificate. Split-state weather HMMs are certified equivalent; a 1/50 emission perturbation is caught on a one-symbol word.
- **Parametric closure loci.** Generic observable, reachable and minimal orders over one real parameter, and *exactly* the parameter values where they drop, computed by Cauchy–Binet, Faddeev–LeVerrier and Sturm sequences without sampling. This complements `closure_conditions`, which tests one fixed encoder. A mirror-symmetric rod is flagged as accidental exactly at t = 1/2.
- **Direction enrichment.** Beyond coordinate subsets: the lift grows by target-visible error snapshots until the exact rational envelope of every supplied scenario meets the tolerance. A six-cell chain is certified to 1/20 with five states.
- **Controlled polynomial lifts.** For x' = F(x, u) with arbitrary inputs, produces exact z' = Σ uᵐ G_m z.
- **Heated-plate application.** In a 12 × 12 plate whose target is the corner sum, the observable and Hankel-certified minimal orders are 17 of 144 states. Reduced evolution matches the full model exactly in rational arithmetic.
- **About 28× faster sparse compilation**, using an incremental echelon form with pivot-column coordinates.

`adaptive_coordinates` adds coordinates according to target-bound improvement per supplied cost until a uniform tolerance is met or the rank budget is exhausted. The guarantee covers every initial state in the stated box and every input within the stated componentwise radii. `optimal_coordinates` performs budgeted best-first search and can establish the least additive cost among coordinate subsets accepted by that particular conservative bound criterion. It does not assert minimum cost among every possible reduced representation. The retained example shows greedy cost 7 versus least cost 6, explicitly separating the heuristic from the optimizer.

`compile_family` finds one encoder closing under every coefficient operator, so it remains exact under arbitrary time-varying coefficient combinations. `closure_conditions` derives affine parameter equations for where a supplied fixed encoder closes. `compile_output_memory` derives a minimal scalar output recurrence, including input-memory kernels, from the supplied linear system. Its replay checks rational identities rather than fitting observed time-series values.

## Demonstrated results

The suite has **148 test methods**. Version 0.7 adds independent exact-Lyapunov-equation checks of every stability decision (280 random matrices), containment of exact finite suprema in all-time brackets, attained refutations, vertex enumeration for zonotopes and box/zonotope agreement. Version 0.4 adds brute-force word enumeration against automaton minimization and equivalence (including the shortest-counterexample claim), random Markov-parameter and Hankel-rank comparisons for realizations, pointwise rank checks against predicted parameter exceptions, and CLI round trips of every example. Earlier tests include the exhaustive 324 two-state partial-machine corpus, 60 random rational forced-system reductions, 30 random approximate-bound comparisons, 24 random forced output-memory models, box-corner checks, packet-mutation rejection and trillion-step exact affine composition. A 64-site ring aggregate compiles to one state with multiplier 99/100. A stable nonnormal example exposes a first-step hidden-state output error of 8 and therefore rejects a tolerance-1 usable horizon beyond the initial time.

The new eight-state attenuated-transport demonstration uses ranks **2, 3, 4 and 8** for target tolerances **1/10, 1/100, 1/1000 and zero**, respectively, over eight steps. These are uniform bounds over the declared initial box and forcing radii. The driver example reduces its worst envelope from 13/4 to zero by adding one coordinate. The parameter example requires two states across the family, while a one-state encoding closes only at parameter zero.

The optional benchmark in `examples/benchmark_ring.py` compiles a 2,048-state periodic stencil to its one-dimensional aggregate. For 256 queries of 200 steps, the retained local receipt records full execution at about 0.478 s, reduced execution including encoding at about 0.000422 s, and construction plus identity replay at about 0.121 s. The first batch is about **3.94× faster including construction**; the largest output difference over all sampled times is about 5.68e−14. This is an exactly closed aggregate demonstration. It does not reconstruct the full field or establish a generic simulation speedup. Rerun to obtain timings for your machine.
