# External SLICOT benchmark

This is an external-model experiment, with generated controlled scenarios. Its matrices come from the published SLICOT model-reduction collection, not DynaComp's symmetric plate generator. The retained cases are the 200-state thin-rod heat model, the 84-state PDE model and the 48-state building-motion model. The last model is mechanical building motion, not a building thermal model. The exact upstream commit and MAT-file SHA-256 digests are in `slicot_manifest.json`.

Install `python -m pip install -e ".[numerical]" threadpoolctl`. From the repository root run `OPENBLAS_NUM_THREADS=1 python benchmarks/external_slicot.py --download`. On PowerShell, set `$env:OPENBLAS_NUM_THREADS='1'`, then run `python benchmarks/external_slicot.py --download`. The script acquires only the three selected MAT files from the pinned upstream source and checks their hashes. Supply `--data-dir PATH` to reuse previously acquired bytes. Downloaded data are outside the repository and excluded from the release ZIP; the ZIP includes the acquisition script, source hashes, complete timing results and replayable compressed certificates. Source-data redistribution rights are not assumed.

The imported models are continuous-time linear systems. The three cases have identity mass matrix and zero feedthrough. The benchmark explicitly rejects other mass matrices; in particular the published `heat-disc.mat` cannot be used by ignoring its E matrix. Sampling uses the augmented-matrix zero-order-hold exponential, retaining every source state, input and output. Heat, PDE and building sample intervals are respectively 0.1, 0.0005 and 0.01 in their model time units, with twenty steps each. Sampling and binary64 normalization are declared transformations. The rational guarantee applies to the resulting stored binary64 discrete model interpreted exactly as dyadic rationals, not to the continuous differential equation or to expm rounding error.

Each full initial-state component and each input at each time independently ranges over [-1,1]. The original output matrix is divided by its maximum row L1 norm, yielding a common normalized tolerance of 0.01. These coordinate boxes are controlled mathematical workloads; they are not experimentally calibrated physical operating ranges. The original output scale is retained so normalized errors can be converted back to the model's output coordinates. They must not be described as measured temperatures or field data.

DynaComp's numerical discovery begins with the target row and adds output-visible missing directions. Every added basis coordinate is rounded to a dyadic denominator 2^20, while the target is retained exactly. Existing `uniform_enrichment` then constructs the rational projection and computes the sharp box error. Acceptance follows this exact calculation and an independent `replay_uniform`; the floating proposal's apparent accuracy is insufficient. Four- and eight-state budgets are both retained, including rejected proposals. A rank-budget failure refers to that proposed subspace and is not a theorem that no other model at that rank could meet the tolerance.

The standard baseline is square-root balanced truncation, constructed from the sampled model's discrete controllability and observability Gramians. Its left-inverse residual and leading Hankel singular values are reported. Its box diagnostic uses binary64 arithmetic and is explicitly not a rational certificate. Balanced truncation ordinarily targets input-output approximation from rest; arbitrary componentwise initial-state boxes are a different objective. Accordingly the benchmark separately retains zero-initial-state persistent-input errors. A failure on initial-state corners is not evidence that balanced truncation is a poor general-purpose algorithm.

All engines evaluate identical every-time outputs for 256 scenarios. The workload includes random box members, a persistent unit input from rest, a coherent unit initial field and the two DynaComp attaining corners. Single-thread BLAS avoids attributing thread configuration differences to a reduction method. Five warmed alternating trials retain raw timings. Per-batch shape/data/domain checks and reduced matrix assembly are included. Common MAT loading and zero-order-hold sampling are outside repeated execution; sampling is reported separately. Construction and exact replay costs are charged to DynaComp's first batch and amortization. JSON/gzip serialization and network acquisition are excluded and add further startup cost.

Rational packets can have coefficients exceeding Python's decimal-string formatting cap. The command disables that cap only in its own process for the trusted pinned source; library defaults remain unchanged. This is a real deployment cost of exact arithmetic, not evidence that the source model is invalid. Gzipped JSON packets reside in `receipts/external_slicot`. To replay one, use `gzip.open(path, 'rt')`, parse JSON and call `dynacomp.replay_uniform(packet)`; the CLI does not transparently read gzip.

Finite-horizon certificates exclude numerical QR and runtime roundoff. Numerical outputs are checked against the exact bound with a stated small comparison allowance, rather than conflating that allowance with a formal rounding proof. The external experiment does not certify arbitrary parameter switching, continuous-time behavior between sample points, nonlinear physics or behavior after twenty steps. Version 0.7's all-time mechanisms require separate acceptance and are not implied by these benchmark packets.
